# API-router 脱敏能力问题报告

报告日期：2026-10-23（北京时间）\
状态：待修复、待复测\
依据：2026-10-23 脱敏专项测试及其原始证据

## 一、结论

本轮脱敏专项验证未通过。主要问题集中在敏感实体识别、模型输出校验和推理预算三个环节：路由组可能将无效识别结果当成成功并发送敏感原文；严格识别路径则经常因实体位置错误而阻断；真实模型还存在姓名漏检、版本号误检和复杂输入超时。

建议首先修复异常结果放行，再提高实体定位与语义识别质量，最后优化复杂输入的处理耗时。提高 HTTP 成功率不能替代脱敏验收；安全阻断与原文泄漏必须分别统计。

本报告记录的是当次测试候选的行为。生成报告时工作区已有后续运行时相关改动，本次只整理证据，没有重跑测试，因此不将当次预算和缺陷状态自动认定为后续源码的最新结论。

## 四、问题清单

优先级为本报告建议：P0 为需首先处理的敏感原文发送缺陷；P1 为影响识别质量或请求可用性的缺陷。

| 编号 | 建议优先级 | 问题 | 证据状态 |
| --- | --- | --- | --- |
| R-01 | P0 | 路由组将无效识别结果当成成功，继续发送敏感原文 | 故障注入通过真实路由组派发路径复现 |
| R-02 | P1 | 严格识别结果中的实体位置经常不合法 | 真实 1.7B 诊断复现；上游具体成因待细分 |

### R-01：异常模型输出未阻断上游发送

**触发条件。** 路由组开启 `localRedaction`，本地模型 HTTP 返回 200，但结果为以下任一种：空 content、非 JSON、截断 JSON、`finish_reason=length` 的部分实体、未知标签、坏外层响应、空 choices。

合成输入：

```text
请转告宁祁和陆遥明天到场，电话13812345678。
```

**实际结果。** 7 个异常样例全部返回 HTTP 200，模拟上游调用数均为 1，上游捕获到未脱敏姓名。正常完整实体结果的对照样例成功发送，且没有姓名泄漏。

**预期结果。** 无效、不完整或不可校验的识别结果必须报错，上游调用数为 0。只有结构合法且覆盖完整的结果，才能声明识别完成。

**已确认原因。** [detector_llm.go](../internal/routerredact/detector_llm.go) 的 completion 处理和 `ParseLLMContent` 允许异常内容变成空实体或部分实体；[orchestrator.go](../internal/routerredact/orchestrator.go) 后续仍可返回 `Complete:true`。该路径与应用级严格 `PrivacySpecification` 的失败行为不一致。

**建议修改。** 明确区分“合法完整的空实体列表”和“解析失败”；校验响应结构、结束原因、字段覆盖、标签及实体合法性。不能静默丢弃异常结果或未知实体后继续发送。两条识别路径应共用完成性与失败阻断标准。

**验收条件。** 将 7 个异常样例纳入长期服务集成回归，全部断言上游调用数为 0；正常完整结果和合法完整空实体结果仍可完成请求。真实模型漏检属于 R-03，不能只靠结构校验解决。

### R-02：严格实体位置输出不可靠，导致大量阻断

**实际结果。** 56 条固定语料中，17 条因结果无效阻断、2 条超时、1 条达到预期输入限额；10 条留出语料中，2 条因结果无效阻断、1 条超时。结果无效主要表现为：

- `span_bounds`：实体起止位置不合法或越界。
- `span_text`：原文对应位置与返回的实体文本不一致。

4 字段邮箱/工具端到端样例因 `span_bounds` 失败，上游调用数为 0。单字段邮箱样例成功，说明并非所有文本或所有请求均无法完成。

**原因边界。** [privacy_parse.go](../internal/routerredact/privacy_parse.go) 按约定把 Unicode 码点位置转换为 UTF-8 字节位置，并严格核对原文。已确认模型输出未满足约定，尚未证明全部错误均由同一种计数偏差、提示词或模型能力不足导致。不能将校验阻断本身当成安全缺陷。

**建议修改。** 先逐类核对失败原始响应；评估新的版本化抽取协议，让模型返回字段、类别和精确原文子串，由服务端计算位置。重复文本需通过出现序号或上下文消歧，无法确定时阻断。协议变更需同步提示词、schema、解析器、能力指纹、缓存版本与文档，不应在现有严格协议中悄悄增加模糊修复。

**验收条件。** 覆盖中文、emoji、重音字符、重复实体、多字段和跨片段边界；位置必须对应原文字节边界。原有无效结果仍拒绝，真实模型有效结果完成率提高；JSON/SSE 和工具字段的映射与还原同步通过。

### R-03：1.7B 对普通句子中的姓名漏检

**实际结果。** 在 10 个组合检测样例中，1.7B 有两条姓名样例未完成替换：

```text
请转告宁祁和陆遥明天到场。
😀请转告Élodie Durand稍后回电。
```

这些样例生成了可供发送的请求体，但姓名原文仍保留。该证据来自组合检测模块，区别于 R-01 通过服务派发路径实际捕获的模拟上游请求。4B 在相同姓名样例上替换成功，不能据此推导其总体召回率。

**原因边界。** 已确认组合检测的规则、词典和首轮模型结果未覆盖这些姓名。当前 [runtime_redactor.go](../internal/routerservice/runtime_redactor.go) 构造路由组检测器时未开启已有复核选项；尚未验证开启复核后可以消除这些漏检。

**建议修改。** 增加口语化姓名、并列姓名、英文名、重音字符和简称的训练外验收样例；依据“转告、通知、联系人”等上下文触发有预算约束的复核。结构正确的空结果不等于语义上没有敏感信息，模型自报置信度也不能证明没有遗漏。根据独立语料与时延比较决定模型选择。

**验收条件。** 已复现姓名样例中原文不残留；加入未用于提示词调整的独立样例，分别统计放行漏检、阻断和正常文本误伤。

### R-04：数字日期规则误伤版本号

**实际结果。** 两种模型的组合检测均将以下干净文本中的版本号改写：

```text
输入：版本v1.2.3，端口8080，重试3次，成功率99%，今天学习Go语言。
输出片段：版本v<BIRTH_DATE:1>
```

**已确认问题。** [rules.zh.yaml](../internal/routerredact/privacy_assets/rules.zh.yaml) 的 `english_numeric_date` 允许点分数字，未充分排除版本号上下文，能够命中 `1.2.3`。换用 4B 后同样出现误判，不能仅靠替换模型解决。

**建议修改。** 增加版本号和软件标识边界排除；校验真实日期范围；区分生日、合同日期和普通公开日期的处理策略。避免将所有数字日期统一按出生日期处理。

**验收条件。** `v1.2.3`、软件包版本、端口、百分比和重试次数保持原样；应保护的真实生日、合法敏感日期仍按策略处理。

### R-05：复杂输入在完成识别前耗尽预算

**实际结果。** 1.7B 的 10 字段姓名/邮箱/工具/数字样例在 15 秒耗尽预算，上游调用数为 0。4B 的提示注入样例和长文本分块样例约 15 秒失败，均未生成可供发送的准备结果。

**已确认因素。** 当次组合 Pipeline 上限为 30 秒，但普通诊断 Manager 的 redaction 默认预算为 15 秒，内层先结束。4B 合成样例单条耗时约 2.93–15.03 秒。本轮未复制普通服务的 65,536 上下文等自定义设置；这些数据不代表真实服务配置下的性能，后续预算相关改动需单独复测。

**建议修改。** 入口确定统一总截止时间，排队、推理、复核、批次和重试共用剩余预算；按 token 与预计输出规模分批，减少重复提示内容。复用已有会话缓存并保持版本隔离。长文本切块需验证完整覆盖、边界重叠与去重，任一块未完成时不得将部分结果声明为完整结果。

**验收条件。** 统一配置下测试两种模型，记录排队、加载、各批次推理和总耗时；P95 应满足预先约定的总预算。超时、取消和重试后槽位必须释放，敏感原文不得因预算不足而直接发送。

## 六、已通过项、验收缺口与修复顺序

已通过：Linux/Windows 构建；8 包 race 的 2,228 个测试及子测试，0 跳过；相同包 vet；Chromium/WebKit 脱敏页面；真实单字段邮箱的请求替换、JSON/SSE 还原；模型取消释放槽位及关闭回收。组合检测中成功准备的结果，除金额按设计泛化外，本轮原文还原成功。

验收缺口：真实工具复杂场景未完成；取消后的恢复请求虽返回 HTTP 200，但因 `span_bounds` 解析失败，后续 100ms 父 deadline 验证未执行；4B 的 56+10 严格识别套件未执行，现有固定诊断 CLI 只接受 1.7B；真实第三方云端、WorkBuddy/Loomy 业务交互和全部平台完整产品门禁未执行。

建议分三批修复：

1. **第一批：R-01、R-04。** 修复异常结果放行和确定性的版本号误判，将已复现样例转成长期回归。
2. **第二批：R-02、R-03。** 改善实体定位协议、姓名识别与有条件复核，复测真实模型、工具字段和三种协议。
3. **第三批：R-05 与整体验收。** 统一预算、优化批次和缓存，用独立语料评估真实模型的漏检、误检、额外阻断与 P50/P95 耗时。

每批修改应保留失败阻断行为；提示词、规则或输出协议变化应更新版本与缓存失效条件。正式放开能力前，需要重新取得对应模型、运行时和协议版本的验收证据。
