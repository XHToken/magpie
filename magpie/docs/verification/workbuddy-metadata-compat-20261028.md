# WorkBuddy metadata compatibility audit — 2026-10-28

The reported user-message rejection was reproduced and fixed in the shared
Chat contract. This checkout was isolated from the user's other local changes.
The installed service and host configuration were not switched or rewritten.

## Observable change

WorkBuddy 5.8.3 spreads providerData into user/system/assistant Chat messages
and assistant/tool history. The shared registry now accepts its evidenced
request IDs, turn/queue/task bookkeeping, summaries, hook details, approval
metadata and tool-continuation fields with their source-derived roles and JSON
types. User command goal status and typed text attachment references are also
covered. The model builder's thinking budget and growth-event extras are
preserved natively. See `magpie/docs/subsystems/api-router-codec.md` and the
fixture README for responsibilities, source hashes and limits.

All 109 fixtures pass through input validation, routing normalization and
native forwarding without losing fields. The product HTTP matrix exercises
direct/cloud-judgment/unavailable-judgment routing with JSON and SSE. Metadata
strings/keys, including nested arrays and attachment references, remain scanned
by privacy preparation. Invalid types, duplicate keys and unrepresentable
cross-protocol metadata retain explicit errors before outbound work.

Fixtures were generated by the installed serializers with synthetic inputs;
they are not literal wire captures of every WorkBuddy workflow, nor a claim of
media support or compatibility with future client fields.

## Regression proof

Before the change, `TestInstalledHostFieldContractAcrossValidationRoutingAndNativeCloud`
failed on current user prompts, correlation IDs, queue/hook/tool metadata with
`unsupported or invalid model input`.

A separate Go overlay then removed only startsNewUserRequest and the user role
of conversationRequestId from the final registry, without changing working
sources. The two corresponding fixture tests failed with the same error
(exit 1, a behavioral FAIL rather than a compile error). The final registry
passes those tests as part of the complete matrix.
