# 日常使用与进阶任务

只展开用户主动提出的目标，沿用“解释目的 → 用户操作 → 验证结果”的教学方式。已有配置先读状态，不重跑首次教程。页面和能力以安装版本为准。

用户要求“一键安装本地模型”或“一键配置端云协同”时，转 [一键配置](one-click.md)，自动完成推荐、下载、启用及该任务需要的组和宿主接入，不按这里的逐步教学等待每一次点击。

| 用户想做什么 | 教学重点 | 完成依据 |
| --- | --- | --- |
| 给现有应用增加/切换一个云端模型 | 同供应商增加可用模型，或添加另一供应商；更新目标应用的绑定，按需重开并选择模型 | 新会话的对应请求显示实际目标，原有非目标应用配置保持其用户意图 |
| 主模型失败时换备用模型 | 解释路由组将多个目标作为一个选择；在版本支持的顺序/回退设置中选主用与备用，再让应用绑定该组 | 配置与绑定一致，正常请求的实际成员可查；没有真实回退证据时不宣称回退已验证 |
| 多个应用用不同模型 | 每个应用分别绑定所需目标；解释供应商可共享、应用选择可独立 | 分别确认用户指定应用的模型与对应请求，不扩大到其它应用 |
| 看用量和费用 | 带用户区分时间范围、成功/失败、实际执行模型、云端与内部调用，以及估算字段 | 用户能找到某次请求并解释其用量；缺数据时如实说明，不当作精确账单或节省承诺 |
| 重新打开、停止或断开接入 | 说明管理地址、实际启动方式与断开恢复的关系 | 用户知道怎样恢复服务或还原应用；需要恢复时转排障指引 |

## 路由组

用户想配置备用或调度时再介绍。优先用其已有且可用的两个模型讲解一个简单策略，随后让应用绑定该组。不要为讲解主动购买供应商服务、创建一堆组，或故意制造上游故障进行收费测试。用户明确要求验证回退时，先说明该版本支持的测试方式与影响，检查记录中的尝试和实际执行成员。

智能分流、本地判断、排除规则等按用户提出的场景逐步展开，不把“建立组”与“策略效果已验证”混为一谈。

## 本地模型与实验性脱敏

这是按需分支，不是已有 API Key 用户完成云端接入的前置步骤。用户选择后，先确认当前版本支持的系统、硬件、模型、运行时与可用空间，说明下载规模和运行资源，再由用户决定安装与启用。

带用户分别确认模型安装、能力检查、进程健康和应用选择。检测到 GPU 不代表已经加速，应看实际后端与已生效状态。不要将自动化检查通过解释成模型质量或所有宿主兼容性已验收。

实验性脱敏须由用户明确选择，解释其当前试用边界、严格校验失败时的阻断行为和诊断入口；不承诺可靠隐私保护，也不将其默认开启来修复普通云端问题。按对应版本文档操作，不沿用另一版本的模型 ID 或启动参数。

## 教学完成

让用户自己完成一次最小操作，例如切换模型后找到新的请求，或说明如何恢复原来的模型。用户只想解决当下问题时给出结果和后续入口即可，不要求完成练习或继续学习全部功能。
