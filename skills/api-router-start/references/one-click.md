# 一键本地模型与端云协同

本分支是自动执行模式。用户调用后直接完成授权范围内的操作，报告推荐理由、重要进展和最终结果，不逐项要求用户点击。用户说“教我做”则切回对应教学步骤。编辑这个 skill 不等于立即在编辑者电脑下载模型、收费调用或改宿主；只有实际调用配置流程时执行。

需要使用管理 API 自动执行时，再读 [接口线索](automation-api.md)，先核对安装版本；本参考中的操作意图优先，示例路径不能代替实际版本契约。

## 两种入口

- **一键安装本地模型**：检查/启动 Wefto → 检测电脑 → 推荐并选择 1.7B 或 4B → 下载所需权重和运行时 → 校验 → 自动启用、加载、健康和能力检查。若用户同时要求“供 Loomy 使用”，再将该本地模型绑定 Loomy 并开启接入，保留原选项；仅安装请求不修改应用。
- **一键端云协同**：复用/完成上述本地模型准备 → 让用户有机会指定云端供应商和模型（已指定不重复问）→ 未指定则用讯飞星辰 MaaS → 等待用户完成 API Key 申请/本机录入 → 验证所选云端模型 → 创建智能端云分流组 → 自动为已安装的 Loomy、WorkBuddy 开启，并将组设为默认、保留原模型选项 → 验证配置及必要的小请求。

默认组策略是项目的 **smart_split 智能端云分流**，不替换为顺序回退。默认云端选“最新正式通用星火模型”，不可用时说明并让用户选，不静默降级或采用预览模型。用户自行选云端供应商/模型时尊重其选择，不强行换为星辰。默认不弹出没有必要的设置问卷。

## 1. 先检查实例、版本和已有状态

按 [安装启动](install.md) 使用正常用户布局，验证实际实例、回环管理 URL、服务身份和私有 token 的归属。检测安装版本及当前版本支持的本地模型目录、硬件推荐、下载管理、能力检查、路由组与宿主事务。接口与页面不符时先读该版本帮助/标签文档；以下 API 线索不能直接套到其它版本。

读取已选本地模型、是否安装/启用/用户禁用、现有供应商、组、应用绑定和宿主恢复记录。用户本次明确要求自动启用，可恢复之前禁用的目标模型；若用户在当前下载过程中主动禁用、取消或改变选择，以最新操作为准，停止对抗式自动启用。

已安装并健康、适合此设备的已选模型优先复用，不为遵循推荐而重复下载另一档；用户指定档位时按设备允许范围验证。需要切换活动模型时通过产品生命周期排空/切换，保留原下载，不直接杀进程。确认版本不具备所需能力时报告，不静默升级或绕过限制。

## 2. 自动推荐：以产品检测报告为准

主动调用当前版本的设备检测，读取 OS/架构、物理与当前可用内存、CPU 线程、GPU/独显专用显存、已确认的 CPU/GPU 后端、模型与运行时所在磁盘空间。优先使用 Wefto 的检测和 recommendation，不只用系统总内存或显卡名称自行分类。

规则：`detection.state` 必须通过；`recommendation.tier` 决定自动选择，`maxTier` 只是允许的上限。16 GiB 机器即使允许 4B，推荐仍为 1.7B 时默认选 1.7B。当前实现可见的参考标准如下，实际运行时以对应版本的完整检测结果为准，不把这些数值硬编码成另一套检测：

| 检测结果 | 自动行为 |
| --- | --- |
| 产品推荐 4B，且检查通过 | 选择目录中对应的 4B 模型 |
| 产品推荐 1.7B，且检查通过 | 选择 1.7B，保留给宿主和系统的资源余量 |
| 低于 8 GiB 总内存、可用内存不足约 2.5 GiB，或 CPU/后端/磁盘检查不通过 | 不强行安装；解释具体阻碍与下一步 |
| 检测未知、模型目录无该平台运行时 | 不猜测支持，不下载任意外部运行时绕过检测 |

当前源码在资源充分的 24 GiB+ 设备，或有经过确认的适合后端与至少 6 GiB 独显专用显存等条件下可推荐 4B；还要考虑可用内存、CPU 和磁盘。GPU 被枚举不等于推理确已加速，Metal/CUDA/Vulkan 是否生效要看最终加载结果。Apple Silicon 统一内存不要作为独显专用显存相加。WSL/虚拟机按实际运行服务可用资源检测，不把宿主的全部资源当成可用配额。

简短报告“检测到的关键配置、建议档位、理由、目录提供的预计下载量与空间”，随后自动执行，不再问一次是否下载。使用当前目录的准确模型 ID；runtime ID 的大小写可能与 `local/<id>` 选择器不同，不能凭展示名拼接。

## 3. 下载后自动启用

通过产品安装器下载固定目录中的权重、匹配平台运行时和依赖，沿用 SHA256、断点续传、空间预留与后端选择。不自行下载一个同名 GGUF 或新版本 4B 替换受支持的模型。已安装且校验通过则跳过下载；有同一安装任务则观察/续接，不重复提交。

轮询真实安装状态和进度，约 10–30 秒一次，向用户报告有意义的进展；下载期间保持交流，单次阻塞等待不超过 60 秒。失败/取消立即读取错误，保留可恢复下载；连续约 5 分钟无字节或阶段变化时检查来源、代理和磁盘并报告阻碍，不无限提交安装。不要因为页面暂时无响应就重装。需要跨对话继续时，仅记录非敏感的模型 ID、安装任务状态和下一步，恢复后重读实际状态。

安装完成必须读回校验/receipt 及 installed 状态。随后按该版本生命周期执行选择、启用、加载、健康检查；自动运行可用的本地判断/执行能力检查。仅在所需检查通过、产品允许时启用智能分流所需的 judgment/execution 试用开关。调用“一键端云协同”已授权这些必要的本地功能，短说明其当前试用性质即可，不反复问；**不启用 redaction 脱敏或服务的 experimental-redaction 参数**。

成功是目标模型已选、启用、实际加载且健康，所需能力有通过证据；不是只看下载进度 100% 或 enabled。能力不可用或检查失败时报告“已下载/已加载，但协同能力未就绪”，不打开无效路由组、不把纯云端组称为端云协同。CPU 回退但检查通过时说明实际后端，不声称 GPU 加速。

## 4. 云端选择与等待 API Key

用户已指定可用供应商/模型时复用；尚未选择时用一句话给选择机会：“云端可指定已有供应商和模型；不选就用讯飞星辰的最新正式通用星火模型。”可以在等待期间继续独立的本地准备，但没有回复前不要立刻覆盖明确的现有云端意图；用户选择默认或合理机会后仍未指定时说明采用默认。

默认平台是 **讯飞星辰 MaaS**（`spark-maas`），不是旧星火 HTTP 平台或 Coding Plan 的另一套凭证。打开 [星辰平台](https://maas.xfyun.cn/) 与 [API Key 页面](https://maas.xfyun.cn/apikey)，按当前官方页面引导用户自行登录、申请/开通所需 API 和填写凭证。不要代为注册、接受付费订阅或购买额度。

缺少 Key 时，等待用户在 Wefto 本机供应商表单保存或使用平台认可的本机安全录入方式；不要请求把 Key 发到聊天、传命令行参数、写入脚本或进度文件。用户说“填好了”后，重新只读确认 `hasKey` 等状态，并继续自动选择、验证、建组、接入。若必须结束本轮以等待用户，明确已完成本地准备、尚缺凭证、回复“已填写”后会继续；不轮询申请网页、不创建后台监控来等待，不将 pending 称为完成。

### 执行时再确认“最新”

每次创建时查询星辰官方模型广场/接口文档和用户授权的模型目录，区分正式、预览、已下线模型以及 Key 所属平台。仅在 **星火通用云端大模型** 范围选择最新正式可用版本，不将平台上的第三方模型、小参数云端 1.7B/4B、Coding Plan 的 Auto 当成默认旗舰。不能按字符串排序、预置列表的第一项或模型名猜发布时间/正式状态。

官方来源：[模型广场](https://maas.xfyun.cn/modelSquare)、[产品文档](https://www.xfyun.cn/doc/spark/产品使用说明.html)、所选版本的具体接口文档。当前资料可能有 Spark-X2.5 与更新系列并存，**不能把这个 skill 编写时看到的 ID 永久写成“最新”**。官方与目录冲突或无法确认正式状态时说明候选并请求用户选择，不偷偷沿用旧预设。

根据所选模型的官方文档匹配协议和 Base URL。Chat、Responses、Anthropic 的路径不同，不凭客户端名称直接复制完整资源 URL 到 Base URL。申请成功不等于有模型权限；选择后以一次小的生成验证权限/协议/模型。说明按平台规则计费，已授权测试不再确认。不批量付费探测、不在 401/403/模型不存在时反复重试或静默换旧模型；让用户选可用候选或补齐权限。

## 5. 建组：下载好的端侧模型 + 选定云端

读取实际 catalog 中目标本地选择器及供应商生成的 provider ID/准确云模型 ID，创建一个普通可见、已启用的“端云协同”组，使用当前版本智能分流策略 `smart_split`，成员至少包含已下载启用的本地目标和已验证的云目标。需要 classifier 时绑定同一个本地模型，按该版本 schema 设置，不猜字段。保留产品标准上下文和预算，不为一键配置全局调参；默认不启用组脱敏。

解释为“简单请求可优先本地，复杂请求交给云端，失败与回退按当前版本能力执行”，不承诺所有敏感数据都留本地、保证节省额度或每条请求都由本地执行。智能分流是策略，实际路径由请求和运行状态决定。

再次调用时，先按准确 ID/成员/策略和用户意图找已有组；相同配置复用。仅同名却成员不同不覆盖，使用明确不冲突名称并说明；已有组正在使用或用户编辑过时按最新 revision 处理，冲突不反复覆盖。保存后重新读取组，确认目标可用、未禁用、未被排除；不把保存成功当作实际分流已验证。

## 6. 自动接入 Loomy 与 WorkBuddy

先逐个发现是否安装、正在使用的配置根和原始绑定。**保留原有模型选项，新路由组排在第一位作为默认**，用去重列表 `[group/<实际ID>, ...原选项]` 提交；不能删除用户自己的供应商、模型、扩展字段、初始恢复快照。新旧产品供应商键按当前宿主适配器兼容处理，不手改成统一字符串。

通过页面连接动作或当前版本受支持的 authenticated host transaction 自动开启接入并读回状态；不要只写 AppProfile 或组而漏掉宿主事务。目标应用未安装就跳过，保留路由组并提示将来安装后可接入；不安装 Loomy/WorkBuddy 本体、不创建假的宿主目录。多个候选配置根、恢复冲突、未知路径时只暂停该应用，其他独立部分继续，明确部分完成。

不强退正在工作的应用；报告需要用户结束任务后完全重开以加载设置。若宿主缓存旧模型、保留会话或项目级配置覆盖默认，不能仅凭全局配置保证正在运行的会话已切换。让用户重开并新建会话，必要时用该版本支持的宿主/页面操作选择新组。自动“开放使用”与“真实对话已验证”分开报告。

## 7. 验收、重复执行与失败处理

分别报告：推荐档位/原因、下载/启用/实际后端、判断执行检查、云端平台/确切模型/正式状态来源、组与策略、每个应用的连接与默认选项、待重开/跳过/冲突项。

用最小真实请求验证云端和可用的路由链路，并通过请求记录查看组、实际成员、判断/回退信息；不要为了制造“本地一次、云端一次”无限尝试收费调用。没有分流两条路径证据时仅宣称配置/已测试路径通过。宿主真实调用尚未测试时请用户在新会话发一个小消息，再查对应记录。

本地不就绪、Key 缺失、云端无权限、建组失败或某应用接入冲突时保留已完成进度和原配置，准确报告阻碍；不进行假成功、无提示纯云降级、清空数据或删除恢复记录。每个请求只执行其必要的自动操作，重复调用不创建重复供应商/组/下载任务。用户中途收回授权或改变选择时以最新意图为准。
