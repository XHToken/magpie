# 排障与恢复

先确定用户原来的目标，以及问题发生在服务、供应商、模型、应用配置还是实际请求阶段。只展开与症状匹配的检查；解决后返回原来的教学步骤。下面的原因是排查方向，不是看到一个状态码就能确认的结论。

原任务为 [一键配置](one-click.md) 时，修复后继续已授权的自动流程，不要求从头逐步点击。下载完成不等于已加载；本地健康不等于判断/执行能力已通过；Key 已保存不等于云端可生成；组保存不等于两款宿主的接入已完成。按这几层分别诊断并保留已完成状态。

| 现象 | 先看什么 | 带用户做的下一步与验证 |
| --- | --- | --- |
| 管理页面打不开 | 实际服务状态、真实管理 URL、前台终端是否仍在 | 复用正确实例；按实际启动方式恢复，重新打开返回的地址 |
| 供应商保存成功但列表为空 | 列表获取结果、缓存/预设来源、平台是否支持列举模型 | 核对接口文档；支持手填时填写有权限的准确 ID，再验证一次生成 |
| 认证或权限错误（如 401/403） | 失败阶段、平台、协议、Key 存在标志、模型权限 | 让用户在供应商页面检查或重新填写对应 Key；重试一次最小验证，不展示原 Key |
| 找不到接口或模型（如 404） | API 基础地址、协议、准确模型 ID | 按该平台文档检查路径和权限；不盲目增删 `/v1` 或切换协议 |
| 超时、限流、余额/配额提示 | 页面错误类型、失败阶段、供应商状态或用户自己的配额信息 | 按原因调整一次或等待；不连续重试、不自动换供应商或批量探测 |
| 应用显示已接入，却仍用别的模型 | 应用内的模型选择、是否完全重开、是否新会话 | 由用户选中绑定模型并新建会话，发送小消息，再查对应请求 |
| “需要重新连接”或宿主目录不明确 | 目标应用的真实目录、绑定目标、服务地址、恢复记录 | 使用项目页面支持的重连接入流程，确认范围后操作；不直接覆盖 JSON |
| 应用有回复但 Wefto 没有记录 | 请求时间、过滤条件、保留设置、应用目标和实例 | 找到对应记录或明确指出链路仍未证实；不凭回复宣称经过 Wefto |
| 本地模型或脱敏流程失败 | 用户是否主动选择该功能、该版本能力与诊断状态 | 转入对应进阶指引；不把启用实验功能当作云端接入的必需修复 |
| 更新后不能启动或新旧数据冲突 | 旧/新版本、真实 dirs、备份、锁归属 | 保留两个布局和失败现场，转 [更新指引](update.md)；不自动合并或降级数据 |

## 交互与证据

一次只请求最有用的缺失信息，例如当前页面的错误提示和发生时间。能只读核对的版本、服务、连接状态直接检查。看不到页面时明确说明；截图应遮住密钥，日志只取与该请求相关且已脱敏的片段。不索取完整 credentials.json、管理令牌、完整配置或整段私有对话。

以当前安装版本的页面、帮助和接口为准。连接检查、模型获取和真实测试可能访问上游；不将它们当作无副作用的状态读取。不靠反复切换设置试错；相同修复没有新证据时停止重复，说明仍缺少什么。

修复默认由用户在管理页面操作，助手解释该操作的目的和影响；用户明确要求代做时仅执行该步。已有授权无需重复确认。不要为排障索要或复述密钥。

## 安全断开与恢复

用户想停止使用某个应用的 Wefto 接入时，先完成其正在运行的任务，关闭目标应用，再让用户使用该版本页面的断开/还原入口。解释“停 Wefto 服务”和“恢复应用原连接配置”是两个独立动作。

恢复提示冲突时保留用户改动、原始备份和恢复记录，读该版本的预览与恢复说明，再处理具体冲突。不删除恢复记录、不覆盖宿主文件来强行让开关变绿。离线恢复仅使用该版本实际提供的 `host ... --help` 和项目恢复命令。

只需重开管理页时给实际管理地址；关闭网页不代表后台服务已停止。用户要停止服务时根据后台服务或前台 start.sh 的实际方式指导；不杀端口占用者或未经核验的进程。

## 暂时无法完成时

明确交接：目标、已验证的步骤、具体错误/缺少证据、保留下来的配置和下一步。不能把重新安装、清空数据或开启额外实验功能作为通用恢复方法。
