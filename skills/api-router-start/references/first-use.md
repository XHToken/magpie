# 首次使用：亲手接入一个应用

适用于已有 API Key、尚不熟悉 Wefto 的用户。下面是可分支的教学主线；根据现状跳过已完成步骤，不一次性把整份文件发给用户。每一轮给当前操作、必要解释和成功标志，需要反馈后再继续。

用户选择一键本地安装/端云协同时改用 [自动配置流程](one-click.md)。该流程可先准备本地模型，再等待用户申请并在本机录入云端 Key，不要求用户先自行完成本教程。

## 1. 明确一个目标

确定用户要接入的应用、API Key 所属平台，以及想用的模型。已知的信息不要重复问。用户还没选模型时，等模型列表出来再让其选择，无须先讲路由策略。

可用开场：“我们先让一个模型在你的常用应用里跑通，再看怎么确认请求。你准备接入哪个应用？API Key 属于哪家平台？”这里的平台名称不是密钥。

如用户只有聊天产品的登录账号或订阅，尚无可调用的 API 凭证，应说明当前缺少 API 访问条件；不让用户把网页会话令牌填成 API Key，也不承诺订阅自带 API 额度。

## 2. 打开正确的管理页面

先只读确认实际安装版本与服务。已有可用实例时复用，给出其真实管理 URL；缺少安装或启动前提时转 [安装启动](install.md)，完成后回到此处。遵循用户对自己操作或助手代做的选择及已给出的授权。

教用户：“浏览器页面用来管理配置，后台的 Wefto 服务负责接收应用请求。关闭网页后，后台服务可能仍在运行；前台 start.sh 则需要保留终端。”按实际启动方式解释停止方法。

成功标志：真实管理地址可以打开，版本与本机实例一致。用户浏览器打不开时先排障，不继续让其填写配置。

## 3. 添加供应商与模型

在当前版本的供应商页面带用户逐步操作：

1. 选择与 API Key 对应的平台预设，或其文档支持的自定义接口。解释“供应商保存连接模型服务所需的地址、协议和凭证”。
2. 用户亲自在页面填写 API Key 和必要地址。预设已有正确地址时不要要求再改；自定义地址/协议不明确时，核对该供应商的官方 API 文档再继续。不要凭模型名猜协议，不盲目添加 `/v1`。
3. 保存后，先确认保存结果，再引导查看或获取模型列表。说明“模型是你具体要调用的目标，准确的模型 ID 决定请求发给谁”。第一次只选用户有权限的一个模型。
4. 当前版本若提供相应连接检查，按页面说明执行一次并读结果。检查会访问上游时如实说明；已授权验证不重复确认。没有该按钮时，以该版本支持的应用检查或后面的真实对话验证，不编造入口。

保存成功表示配置已写入；列表可能来自缓存或预设。能列出模型，也不能单独证明该 Key 可以完成生成。给用户准确说明当前已验证到哪一步。

成功标志：供应商已保存、密钥状态存在、目标模型可供选择，已执行的检查结果明确。模型获取失败但保存成功时保留配置，按错误排查；平台支持手填模型 ID 时可依据官方文档填写，再验证生成，不把空列表等同于无权限。

## 4. 将模型绑定到目标应用

打开该版本的“应用”或“Agent”接入页面，找到用户指定的应用。首次可从受支持的 WorkBuddy 或 Loomy 开始，其他应用以该版本真实支持能力为准。

让用户为该应用选择刚才的供应商/模型，并使用页面支持的连接操作。解释“供应商负责模型服务连接，这里的选择决定这个应用使用哪个目标”。首轮不要求创建路由组。

开启接入会修改该应用的连接配置，操作前说明影响范围及对应的断开/还原入口。默认由用户点击，使用项目的配置事务和恢复能力。多份宿主目录候选时先确定实际使用的目录，不猜测、不同时修改所有候选。

成功标志：页面显示连接状态正常，所选模型正确，没有“需要重新连接”等未解决提示。配置一致性检查通过仍需要后面的真实对话。

## 5. 在应用里完成第一次对话

引导用户按当前版本要求完全退出再打开目标应用，在应用的模型选择处确认 Wefto 对应供应商与目标模型，再新建会话。已有会话可能仍保留旧选择。

首次真实云端请求前简短说明按供应商规则计费。让用户发送一个不含业务资料的小消息，例如“请简短回复：连接测试成功”。若应用会自动执行工具，选普通对话或简单任务，避免把测试扩大为文件修改或长时间工作。

成功标志：应用返回了正常回复。尚不能仅凭回复断定请求经过 Wefto，继续下一步。失败转 [排障与恢复](troubleshooting.md)，保留已经完成的配置。

## 6. 找到并理解对应请求

让用户回到 Wefto 的用量/请求记录入口（名称以当前页面为准），刷新并按刚才的时间、目标应用与模型定位请求。解释最少必要信息：请求是否成功、实际执行的模型、失败时在哪个阶段。

如果使用路由组，应确认实际执行成员；不要只把组名当作最终模型。用量或费用字段为估算、缺失或不完整时按页面含义解释，不承诺等于供应商账单。

找不到记录时先核对时间、过滤条件、保留设置、实际服务地址、应用模型和新会话。若用户关闭了记录，不自动改变其保留意图；说明目前缺少此证据，让用户选择临时开启该版本支持的最小记录或采用其它可核验的诊断方式。没有证据时只报告对话已回复，Wefto 链路仍待确认。

完整成功标志：应用的真实回复与 Wefto 中对应的成功请求相符，用户知道本次使用的供应商和模型。

## 7. 帮用户独立再做一次

可邀请用户自己再发一条简短消息，再找到新的请求记录，不逐步代点。如果用户找不到，只补充其缺少的一步。用户选择停止练习时不阻拦。

结束时用几句话概括：接入了哪个应用与模型、怎样重新打开管理页面、如何在应用里选择模型/新建会话、在哪里查看请求和断开还原。只推荐与其目标相关的一个后续方向；不要求继续学习路由组、本地模型或脱敏。

## 返回用户中断的位置

例如用户说“供应商已经加好了，但应用没生效”：先核对供应商/目标和应用状态，从绑定或应用模型选择开始。不要重新索要 Key、重新安装或清空配置。对话交接只记录非敏感目标、已证实结果、当前阻碍和下一步。
