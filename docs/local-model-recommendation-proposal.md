# Spark-X2.6 端侧模型推荐策略（已批准）

状态：2026-10-27 已获用户批准，已按本标准落实并更新正常目录运行服务。验证范围与记录见 [实施记录](local-model-recommendation-implementation.md)。阈值仍是保守初值，未经真实权重推理校准。

## 设计基线

- 支持 Spark-X2.6-4B-Q4_K_M 和 Spark-X2.6-4B-Q8_0；权重分别为 3,543,441,312 和 4,375,021,824 字节。
- 保留当前 65,536 token（64K）上下文、单推理进程及既有生命周期；不靠自动降低上下文让设备通过推荐。
- 目标是保留系统、Loomy/WorkBuddy 等应用的使用余量。推荐成功不等于已加载、实际加速或质量验收成功。
- 本文所有新内存、显存、速度门槛均为建议的首版保守策略，尚未经两款模型的实际推理校准，不是官方最低硬件要求。
- 容量计算统一使用 GiB（1 GiB = 2^30 字节）；下载文件大小可另以十进制 GB 展示。

运行内存需要考虑模型、上下文/KV 缓存和计算缓冲等，不能只按 GGUF 文件大小判断。依据：[固定 b10828 的内存估计与拆分实现](https://github.com/ggml-org/llama.cpp/blob/b10828/common/fit.cpp)。

## 一、推荐结果

| 结果 | 含义 | 页面与 skill 的自动动作 |
| --- | --- | --- |
| 不建议下载端侧模型 | 已知硬件偏弱，不适合当前两款模型的常规使用 | 推荐云端；跳过本地模型下载与自动启用 |
| 暂不建议下载 | 当前空闲内存/磁盘不足，或关键检测结果未知 | 说明具体短缺或未知项；关闭应用、清理空间或补充检测后再评估 |
| 推荐 Q4_K_M | 满足常规资源条件 | 默认选择 Q4，仍需用户点击下载安装或实际调用已授权的一键安装流程 |
| 推荐 Q8_0 | 满足更严格的加速设备条件 | 默认选择 Q8，同时允许用户选更省资源的 Q4 |

“硬件偏弱”和“资源暂时被占用”必须分开：16 GiB 电脑当前只有 5 GiB 可用内存，应提示稍后重测，不应直接说电脑硬件太差。

## 二、首次安装的推荐门槛

先检查当前系统/架构有固定目录中的兼容运行时，且资源数据可信。再按以下规则计算模型候选；每个候选还须单独通过磁盘检查。

### 推荐 Q4_K_M

共同条件：总物理内存至少 **16 GiB**，当前可用物理内存至少 **8 GiB**。

再满足以下任一路径：

| 推理路径 | 额外条件 |
| --- | --- |
| CPU | 至少 8 个逻辑线程 |
| 独显加速/混合推理 | 至少 4 个逻辑线程，确认存在兼容的 CUDA/Vulkan 后端，单张 GPU 扣除保留量后可用显存至少 4 GiB |
| Apple Silicon 统一内存 | 至少 4 个逻辑线程，确认 Metal 后端支持；使用上述系统可用内存条件，不额外相加“显存” |

集成显卡、软件渲染器或尚未确认的 GPU 不提供加速升档依据；CPU 条件满足时仍可按 CPU 路径推荐 Q4。独显路径允许部分卸载，不承诺全部模型在 GPU 上运行。

### 自动推荐 Q8_0

满足以下任一路径，并且 Q8 自身的安装空间足够：

| 推理路径 | 总内存 | 当前可用内存 | CPU 逻辑线程 | 加速条件 |
| --- | --- | --- | --- | --- |
| 独显 | ≥16 GiB | ≥8 GiB | ≥4 | 兼容 CUDA/Vulkan 已确认；单张 GPU 总显存 ≥12 GiB，扣除保留量后可用显存 ≥9 GiB |
| Apple Silicon 统一内存 | ≥32 GiB | ≥12 GiB | ≥8 | Metal 后端支持已确认；统一内存只计一次 |

- 独显保留量为 `max(1 GiB, 总显存 × 15%)`；可用预算为 `当前空闲专用显存 − 保留量`。不能拿标称总显存代替当前空闲显存，不能累加多张显卡或系统共享显存。
- 加速支持已确认表示硬件/驱动与目标后端的兼容性有可靠证据；实际卸载与推理仍需安装后验证。无可靠确认结果时不自动推荐 Q8。
- 纯 CPU 设备即使有 32/64 GiB 内存，默认仍推荐 Q4。总内存或线程数不能证明 Q8 的交互速度更好。
- 用户明确指定 Q8 时，允许在纯 CPU 设备上手动试用：建议安全预算为总内存 ≥16 GiB、可用内存 ≥12 GiB、逻辑线程 ≥8，并单独通过磁盘与加载检查；提前说明可能比 Q4 更慢。
- Q8 保留更多权重量化精度，但不承诺业务回答质量更好或运行更快，最终以实际任务验证。

## 三、“不建议下载”的判定

| 已知情况 | 推荐结果 | 原因与后续 |
| --- | --- | --- |
| 不受支持的系统/架构，或没有兼容的固定运行时 | 不建议下载 | 当前版本无法提供受支持的本地运行路径 |
| 总内存 <16 GiB | 不建议下载 | 首次自动推荐优先保证 64K 上下文与宿主应用余量；建议使用云端 |
| 无可确认的加速路径，CPU 逻辑线程 <8 | 不建议下载 | 常规 CPU 交互体验风险较高；仅看能否加载不足以推荐 |
| 硬件达标，但当前可用内存 <8 GiB | 暂不建议下载 | 提示关闭应用后重新检测；不将临时占用归为硬件过差 |
| Q8 条件满足但 Q8 磁盘空间不够，Q4 条件与空间均满足 | 推荐 Q4 | 明确说明因空间选择 Q4 |
| 两款模型的安装空间都不足 | 暂不建议下载 | 展示目标磁盘、当前可用空间和各模型所需空间 |
| 总内存、CPU/必要 GPU 支持、磁盘等关键数据缺失 | 暂不建议下载 | 说明无法确认哪一项，不把未知当成零，也不宣称电脑硬件差 |

这些是自动推荐标准，不应全部做成强制封锁。用户主动要求手动试用时，仍需满足目标模型的安全资源预算与运行时兼容性。Q4 手动试用至少需要 8 GiB 可用内存、4 个逻辑线程和足够磁盘；Q8 的预算见上表。不支持的运行时、无法确认/明显不足的必要资源不能绕过。不会为了人工试用偷偷降低 64K 上下文。

GPU 支持缺失时：若 CPU 路径完整满足条件，按 CPU 推荐；若需要依赖 GPU 才能达标，但其支持情况未知，则返回“暂不建议下载/需要重新检测”，不武断归类为硬件差。

## 四、磁盘按模型、安装计划和目标卷分别计算

不再使用整个 4B tier 中最大的安装空间作为 Q4 和 Q8 的共同门槛。

建议每个目标卷的规则：

`所需可用空间 = 目标模型及本次所需组件的安装峰值预留 + max(2 GiB, 峰值预留 × 10%)`

- 模型峰值先沿用固定目录该模型自己的 `InstallationBytes`，包含中断替换等预留；运行时包括下载、解压、依赖与执行目录组合峰值。
- Q4 只用 Q4 的模型预留；Q8 只用 Q8 的模型预留。共享目录或共享组件在安装计划中避免重复计算。
- 首次 CPU 安装的量级约为 Q4 **10 GiB**、Q8 **12 GiB**（含本草案额外余量）；GPU 包可能需要更多，页面必须以实际组件计划为准。
- 已校验缓存可在安装计划能够证明减少新增空间需求时抵扣。损坏、未校验或只存在同名文件的缓存不抵扣。
- 已经完整安装并校验通过的模型不重复套用首次下载空间门槛来阻止复用。
- 模型、运行时位于不同卷时按各卷分别核验；不能把一个卷的空闲空间加给另一个卷。

## 五、决策顺序、已运行模型与信息可信度

1. 读取实际 catalog、平台运行时与用户意图。只支持当前目录中的两款 X2.6；不恢复 X2.5 的下载入口。
2. 已明确指定模型时，检查该目标的兼容性、安全资源与磁盘预算，尊重指定；默认推荐不覆盖用户选择。
3. 未指定且当前已选模型已经校验、加载健康、近期运行正常时优先复用，不为追逐更高档位重复下载或打断请求。
4. 首次安装按 Q8 推荐条件、Q4 推荐条件依次判断；Q8 不满足而 Q4 满足则选 Q4；两者都不满足时区分硬件不足、临时资源不足、信息未知。
5. 拒绝或暂缓时给出具体原因和可执行的下一步；没有合格本地模型时，不把纯云路由组包装成端云协同。

动态资源建议采样 3 次、间隔约 1 秒，使用最低可用值作为本轮推荐依据；首次下载/冷加载前再次检查。检测本身不下载模型、不加载推理进程。

已运行模型已经占用了内存，不能再用“加载后空闲内存”去要求它额外拥有完整的首次加载预算。复用依据为当前绑定的实际健康、运行与压力信息；评估下载第二款/切换到另一款时另算新增/切换需求。禁止为检测而自动卸载正在工作的模型。

## 六、下载后确认实际体验

只验证用户选择并已安装的模型，不自动下载两款来跑比较测试：

- 保留现有哈希校验、加载、健康、工具/判断执行能力检查。
- 校验实际后端与卸载情况，硬件名称不能作为加速成功证据。
- 加速失败时重新按 CPU 条件评估。满足时说明 CPU 回退；不满足时报告当前方案不合适，不强行加载，也不自动另下载一款。
- 建议增加独立的轻量体验采样：64K 分配下，预热后使用固定约 1024-token 的合成输入、生成至多 96 tokens，最多两次，不用私人请求或云端付费调用。它不证明满 64K 真实业务性能。
- 首轮体验提示门槛建议为：每次有效采样至少实际生成 32 个回答 tokens；两次有效采样的中位数中，生成速度 <5 tokens/s 或首个可见回答 token 等待 >15 秒，标为“已可运行，但不建议自动用于端云协同”。不足两次有效采样时不作速度分档，显示“性能待确认”。加载/健康/能力失败仍按原有失败流程处理，不被“待确认”掩盖。这些速度值也须实测校准。
- 检测或性能结果不主动卸载、删除用户模型，不影响正在执行的任务；新证据用于提示和后续自动启用决策。

## 七、用户界面与 skill 一致

页面与 skill 消费同一份后端推荐结果，包含推荐状态、准确 catalog 模型 ID/量化、原因、缺少或不足的资源、目标模型与各卷的安装预算。skill 不再自行维护第二套硬件阈值。

文案示例：

- 不建议：“这台电脑的资源不适合当前端侧模型，建议使用云端，无需下载本地模型。”
- 暂缓：“当前可用内存为 6.1 GiB，建议至少保留 8 GiB。关闭部分应用后可重新检测，现在可以继续使用云端。”
- 未知：“暂时无法确认 GPU 后端支持，且 CPU 路径未满足推荐条件。请重新检测。”
- Q4：“根据当前设备资源，推荐 Spark-X2.6-4B-Q4_K_M。”
- Q8：“当前加速设备与可用资源充足，推荐 Spark-X2.6-4B-Q8_0；也可以选择 Q4_K_M 减少资源占用。”

## 八、审核用示例

以下各行除特别说明外，均假定平台、检测结果和对应模型磁盘预算通过。

| 设备/当前资源 | 预期推荐 |
| --- | --- |
| 8 GiB RAM、4 线程、无确认 GPU | 不建议下载，使用云端 |
| 12 GiB RAM、8 线程、无确认 GPU | 不建议首次自动下载；允许满足安全预算的主动试用 |
| 16 GiB RAM、可用 6 GiB、8 线程、无 GPU | 暂不建议，关闭应用后重测 |
| 16 GiB RAM、可用 9 GiB、8 线程、无 GPU | Q4_K_M |
| 32 GiB RAM、可用 20 GiB、16 线程、无 GPU | 默认 Q4；用户指定 Q8 时可按其预算试用 |
| 16 GiB RAM、可用 9 GiB、8 线程、8 GiB 独显（后端确认） | Q4；可用 GPU 卸载量由安装后验证 |
| 16 GiB RAM、可用 9 GiB、4 线程、12 GiB 独显，当前空闲 11 GiB（后端确认） | Q8；扣除 1.8 GiB 保留量后剩 9.2 GiB |
| 上述 12 GiB 独显当前仅空闲 9 GiB | Q4；不能用标称 12 GiB 宣称 Q8 达标 |
| Apple Silicon 32 GiB 统一内存、可用 14 GiB、8 线程、Metal 确认 | Q8；不再额外相加一份显存 |
| Q8 资源达标但空间仅够 Q4 | Q4，并明确空间原因 |
| 当前已健康运行 Q8，但加载后的空闲内存低于首次安装阈值 | 优先复用；不重复计算模型已占内存，不自动下载 Q4 |
| GPU 支持未知，但 CPU 路径完整满足 Q4 条件 | Q4（CPU 候选），GPU 加速尚待确认 |

## 实施与校准

按已批准标准更新设备推荐、逐模型/逐卷磁盘评估、页面文案、skill 消费契约与相关回归。为边界值、未知信息、统一内存、显存保留、GPU 失败回退、已运行模型复用及手动指定建立测试。

实际下载与推理校准作为后续独立验收，先验证获准使用的测试机器与所选模型。首版阈值若与 64K 分配峰值、加载时间或实际交互体验不符，应调整策略并保留依据；不把静态门槛包装成正式性能保证。
